# Деплой на Railway

Сервис — не веб-приложение. Это задача по расписанию: контейнер поднимается, делает прогон, отправляет отчёт в Телеграм и выключается. Порт слушать не нужно.

---

## 1. Переменные

Railway → сервис → **Variables**. Шаблон — `сервис/.env.example`, в репозиторий значения не коммитим.

| Переменная | Где взять |
|---|---|
| `ANTHROPIC_API_KEY` | console.anthropic.com → API Keys. Отдельный ключ, не подписка — тарифицируется по токенам |
| `AVITO_CLIENT_ID` / `AVITO_CLIENT_SECRET` | Кабинет 1 «ГектарЪ». Авито → Профиль → Настройки → Клиенты и приложения. Права: `messenger:read`, `messenger:write`, `items:info`, `user:read` |
| `AVITO2_CLIENT_ID` / `AVITO2_CLIENT_SECRET` | Кабинет 2 «Светлая долина», те же права. Необязательные: не заданы — второй кабинет отключён, инструменты отвечают понятной ошибкой. В инструментах Авито кабинет выбирается аргументом `account: gektar \| dolina` |
| `BITRIX_WEBHOOK` | Битрикс → Разработчикам → Другое → Входящий вебхук. Права: `crm`, `tasks`, `user`. **URL секретен целиком** |
| `TELEGRAM_BOT_TOKEN` | @BotFather → `/newbot` |
| `TELEGRAM_CHAT_ID` | @userinfobot → напишите ему, он вернёт ваш id |
| `KB_REPO_URL` | `https://github.com/irikrafikov-ai/gektar-avito-kb.git` |
| `KB_TOKEN` | GitHub → fine-grained PAT с доступом на чтение к репозиторию базы знаний |
| `AGENT_MODE` | `send` — агент пишет клиентам сам |

Необязательные: `AGENT_MODEL` (по умолчанию `claude-opus-5`), `AGENT_MAX_TURNS` (200).

## 2. Сборка

В корне репозитория лежит `Dockerfile` — Railway подхватит его автоматически и перестанет пытаться угадать язык через Nixpacks. Именно на этом падала сборка раньше: репозиторий состоял из одного Markdown, определять было нечего.

Проверить локально перед пушем:

```bash
docker build -t avito-agent .
```

## 3. Расписание

Railway → сервис → **Settings → Cron Schedule**. Времена в UTC, МСК = UTC+3.

| Прогон | Cron (UTC) | Start Command |
|---|---|---|
| Утренний, 9:30 МСК | `30 6 * * *` | `утро` |
| Вечерний, 18:30 МСК | `30 15 * * *` | `вечер` |

Команда — это **один аргумент**, а не полная строка запуска: в образе прописан `ENTRYPOINT ["python", "сервис/запуск.py"]`, и Railway дописывает аргумент к нему. Диспетчер `запуск.py` по этому аргументу выбирает роль.

Railway запускает одну команду на сервис, поэтому под два прогона нужно **два сервиса из одного репозитория** — с разным расписанием и разным аргументом. Переменные дублируются, образ собирается один.

## 3а. Вебхук: ответ за секунды вместо полусуток

Прогон по расписанию отвечает в среднем через шесть часов. Замер по живым чатам: триггер «ознакомился со спецпредложением» 15.08 в 13:23 — ответ в 17:24; 16.08 в 13:25 — ответ в 16:56. Регламент требует первой минуты, потому что клиент в этот момент в приложении. Вебхук закрывает именно этот разрыв.

### Третий сервис

Из того же репозитория, но **это не cron-задача, а постоянно работающий веб-сервер**. Настройки у него обратные остальным двум:

| Настройка | Cron-сервисы | Сервис вебхука |
|---|---|---|
| Start Command | `утро` / `вечер` | `вебхук` |
| Cron Schedule | задано | **пусто** |
| Restart Policy | Never | **On Failure** |
| Health check | отключён | **`/health`** |
| Публичный домен | не нужен | **нужен** (Settings → Networking → Generate Domain) |

Переменные те же плюс одна:

| Переменная | Зачем |
|---|---|
| `WEBHOOK_SECRET` | Случайная строка. Она становится частью URL и служит паролем: Авито не подписывает запрос так, чтобы мы могли его проверить, поэтому защита — в неугадываемости пути. Сгенерировать: `openssl rand -hex 16` |

`PORT` Railway подставляет сам, задавать не надо.

### Подписка — осторожно, там уже чужой вебхук

На аккаунте Авито **уже висит подписка стороннего сервиса**:

```
https://tools.reyting.pro/api/avito-hooks/messenger/10028/84069402   (версия 3)
```

Судя по всему, именно через неё обращения попадают в Битрикс и открытая линия заводит сделки. Авито нигде не пишет, добавляет ли новая подписка адрес или заменяет единственный. Если заменяет и этого не заметить — сделки перестанут создаваться молча, и обнаружится это через сутки по пустой воронке.

Поэтому подписываться руками через API нельзя, только скриптом: он делает снимок до, подписывает, делает снимок после и сверяет. Пропал чужой адрес — возвращает его на место сам и сообщает об этом.

```bash
python сервис/подписка.py подписать https://<домен>.up.railway.app/avito/<WEBHOOK_SECRET>
```

Посмотреть текущее состояние в любой момент:

```bash
python сервис/подписка.py список
```

Если скрипт напечатал `🚨 ПОДПИСКА ОКАЗАЛАСЬ ЗАМЕНЯЮЩЕЙ` — Авито держит только один адрес, и одновременно наш вебхук с чужим сервисом не уживутся. Это развилка для Ирика, а не техническое решение: либо принимать события у себя и пересылать дальше на `tools.reyting.pro`, либо от одного из двух отказаться.

### Что вебхук делает с событием

Две дороги, и разделены они намеренно:

| Событие | Дорога | Время |
|---|---|---|
| Триггер спецусловий, диалога ещё не было | Шаблон уходит **без модели**, одним вызовом | секунды |
| Всё остальное от клиента | Будится агент на один этот чат | ~минута |
| Наше же сообщение | Игнорируется | — |
| Прочие системные сообщения Авито | Игнорируются | — |

Фиксированный текст вынесен из-под модели не для скорости. 16.08 сервер отправил шаблон с ценой «вместо 300 000 ₽» вместо утверждённых 295 000 и с лишним переносом строки — модель переписала согласованный текст. В быстрой дороге текст является константой, переписать его нечем.

Там же закрыто расщепление сообщения: 15.08 шаблон ушёл тремя отдельными сообщениями (полный текст, голая ссылка, голый «🟢») из-за трёх вызовов подряд. Здесь вызов ровно один.

### Стоп-краны вебхука

Он умеет молчать, и это важнее, чем умение отвечать:

- **Вне 9:00–21:00 МСК** — не пишет, сообщает в Телеграм, текст уйдёт утренним прогоном.
- **Больше 30 сообщений в час** — стоп-кран темпа из рабочего цикла, алерт Ирику.
- **ОТКАЗ, ДУБЛЬ или `LOSE` в Битриксе** — не пишет. Проверка по имени неточная, поэтому неоднозначность (несколько сделок, Битрикс недоступен, имя не определилось) трактуется **не в пользу отправки**: чат уходит агенту.
- **Шаблон в чате уже стоит** — повтор запрещён, будится агент.
- **Повторная доставка того же события** — отбрасывается по id сообщения.

Проверить логику, ничего никому не отправляя:

```bash
python сервис/тест_детекции.py
```

Тест построен на настоящих сообщениях из чата, а не на выдуманных.

## 4. Первый запуск

Не ставьте расписание сразу. Порядок:

1. Задайте переменные, соберите образ.
2. **Deploy → Run command:** `python -c "from интеграции.avito import Avito; print(Avito().whoami())"` — проверка доступа к Авито.
3. То же для Битрикса: `python -c "from интеграции.bitrix import Bitrix; print(len(Bitrix().crm_list(limit=5)))"`
4. Разовый прогон вручную: `python сервис/прогон.py вечер`. Отчёт должен прийти в Телеграм.
5. Только после этого включайте cron.

Каждый шаг проверяет ровно одно звено. Если запустить всё сразу и отчёт не придёт, непонятно, где отвалилось — в токене Авито, вебхуке Битрикса или боте.

## 5. Что смотреть, когда что-то не так

| Симптом | Причина |
|---|---|
| `НЕ ХВАТАЕТ ПЕРЕМЕННЫХ ОКРУЖЕНИЯ` со списком | Переменные не заданы в Variables. Сервис называет **все** недостающие сразу и выходит с кодом 1 — чинить нужно за один заход |
| `--dangerously-skip-permissions cannot be used with root` | Контейнер запущен от root. В образе для этого заведён пользователь `agent` — ошибка означает, что собралась старая версия Dockerfile. Пересоберите с актуального коммита |
| `Forbidden: bot can't initiate conversation with a user` | Боту не написали первым. Откройте его в Телеграме и отправьте `/start` — иначе он не имеет права писать вам |
| Контейнер перезапускается по кругу | Railway → Settings → **Restart Policy: Never**. Это задача по расписанию, а не веб-сервис: при падении её нужно чинить, а не перезапускать |
| `не получен токен Avito: 401` | Неверные `AVITO_CLIENT_ID`/`SECRET`, либо приложению не выданы права мессенджера |
| `crm.deal.list → error` | Вебхук Битрикса без прав `crm`, либо URL скопирован не целиком |
| Отчёт не пришёл, в логах чисто | Неверный `TELEGRAM_CHAT_ID`, либо боту не написали первым — Telegram не даёт писать в чат первым |
| `⚠️ база знаний не обновилась` | `KB_TOKEN` без доступа к репозиторию. **Прогон продолжится**, но агент будет без цен и фактов — отчёт придёт с предупреждением |
| Прогон падает на `max_turns` | Поднимите `AGENT_MAX_TURNS`, либо в чатах накопилось слишком много за раз |
| Вебхук молчит, событий в логах нет | Проверьте `python сервис/подписка.py список` — наш адрес должен быть в выдаче. Если его нет, подписка слетела |
| В логах вебхука `отвергнут запрос с чужим секретом` | В подписке URL с другим `WEBHOOK_SECRET`, чем в Variables. Подпишите заново с правильным |
| В логах `chat_id в событии не найден` | Авито изменило форму payload. Событие печатается в лог целиком — по нему видно новую форму, править `найти_chat_id` |
| Вебхук перезапускается по кругу | У сервиса вебхука Restart Policy должна быть **On Failure**, а Cron Schedule — **пустым**. Заполненное расписание превращает его в разовую задачу |
| Клиент получил шаблон дважды | Авито повторило доставку, а контейнер между ними перезапустился: защита по id сообщения живёт в памяти процесса. Второй рубеж — проверка «шаблон уже стоит» по истории чата, она переживает перезапуск |

Логи: Railway → Deployments → выбрать запуск. Падение прогона отдельно уходит алертом в Телеграм — молчания при аварии не будет.

## 6. Чего сервис не делает

- **Cron-сервисы не слушают порт.** Health check у них надо отключить, иначе они будут считаться упавшими. К сервису вебхука это не относится — он как раз слушает, и health check ему нужен (`/health`).
- **Не хранит состояние между прогонами.** Память — реестр клиентов в репозитории и сам Битрикс. Контейнер одноразовый.
- **Не коммитит журналы обратно в git.** Журнал пишется внутрь контейнера и исчезает с ним; постоянная копия — отчёт в Телеграме. Если нужна история в репозитории, это отдельная доработка: пуш из контейнера требует токена на запись.
