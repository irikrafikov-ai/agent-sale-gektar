# Деплой на Railway

Сервис — не веб-приложение. Это задача по расписанию: контейнер поднимается, делает прогон, отправляет отчёт в Телеграм и выключается. Порт слушать не нужно.

---

## 1. Переменные

Railway → сервис → **Variables**. Шаблон — `сервис/.env.example`, в репозиторий значения не коммитим.

| Переменная | Где взять |
|---|---|
| `ANTHROPIC_API_KEY` | console.anthropic.com → API Keys. Отдельный ключ, не подписка — тарифицируется по токенам |
| `AVITO_CLIENT_ID` / `AVITO_CLIENT_SECRET` | Авито → Профиль → Настройки → Клиенты и приложения. Права: `messenger:read`, `messenger:write`, `items:info`, `user:read` |
| `BITRIX_WEBHOOK` | Битрикс → Разработчикам → Другое → Входящий вебхук. Права: `crm`, `tasks`, `user`. **URL секретен целиком** |
| `TELEGRAM_BOT_TOKEN` | @BotFather → `/newbot` |
| `TELEGRAM_CHAT_ID` | @userinfobot → напишите ему, он вернёт ваш id |
| `KB_REPO_URL` | `https://github.com/irikrafikov-ai/gektar-avito-kb.git` |
| `KB_TOKEN` | GitHub → fine-grained PAT с доступом на чтение к репозиторию базы знаний |
| `AGENT_MODE` | `send` — агент пишет клиентам сам |

Необязательные: `AGENT_MODEL` (по умолчанию `claude-opus-5`), `AGENT_MAX_TURNS` (200).

## 2. Сборка

В корне репозитория лежит `Dockerfile` — Railway подхватит его автоматически и перестанет пытаться угадать язык через Nixpacks. Именно на этом падала сборка раньше: репозиторий состоял из одного Markdown, определять было нечего.

Проверить локально перед пушем:

```bash
docker build -t avito-agent .
```

## 3. Расписание

Railway → сервис → **Settings → Cron Schedule**. Времена в UTC, МСК = UTC+3.

| Прогон | Cron (UTC) | Команда |
|---|---|---|
| Утренний, 9:30 МСК | `30 6 * * *` | `python сервис/прогон.py утро` |
| Вечерний, 18:30 МСК | `30 15 * * *` | `python сервис/прогон.py вечер` |

Railway запускает одну команду на сервис, поэтому под два прогона нужно **два сервиса из одного репозитория** — с разным расписанием и разным аргументом. Переменные дублируются, образ собирается один.

---

## 4. Первый запуск

Не ставьте расписание сразу. Порядок:

1. Задайте переменные, соберите образ.
2. **Deploy → Run command:** `python -c "from интеграции.avito import Avito; print(Avito().whoami())"` — проверка доступа к Авито.
3. То же для Битрикса: `python -c "from интеграции.bitrix import Bitrix; print(len(Bitrix().crm_list(limit=5)))"`
4. Разовый прогон вручную: `python сервис/прогон.py вечер`. Отчёт должен прийти в Телеграм.
5. Только после этого включайте cron.

Каждый шаг проверяет ровно одно звено. Если запустить всё сразу и отчёт не придёт, непонятно, где отвалилось — в токене Авито, вебхуке Битрикса или боте.

## 5. Что смотреть, когда что-то не так

| Симптом | Причина |
|---|---|
| `НЕ ХВАТАЕТ ПЕРЕМЕННЫХ ОКРУЖЕНИЯ` со списком | Переменные не заданы в Variables. Сервис называет **все** недостающие сразу и выходит с кодом 1 — чинить нужно за один заход |
| Контейнер перезапускается по кругу | Railway → Settings → **Restart Policy: Never**. Это задача по расписанию, а не веб-сервис: при падении её нужно чинить, а не перезапускать |
| `не получен токен Avito: 401` | Неверные `AVITO_CLIENT_ID`/`SECRET`, либо приложению не выданы права мессенджера |
| `crm.deal.list → error` | Вебхук Битрикса без прав `crm`, либо URL скопирован не целиком |
| Отчёт не пришёл, в логах чисто | Неверный `TELEGRAM_CHAT_ID`, либо боту не написали первым — Telegram не даёт писать в чат первым |
| `⚠️ база знаний не обновилась` | `KB_TOKEN` без доступа к репозиторию. **Прогон продолжится**, но агент будет без цен и фактов — отчёт придёт с предупреждением |
| Прогон падает на `max_turns` | Поднимите `AGENT_MAX_TURNS`, либо в чатах накопилось слишком много за раз |

Логи: Railway → Deployments → выбрать запуск. Падение прогона отдельно уходит алертом в Телеграм — молчания при аварии не будет.

---

## 6. Чего сервис не делает

- **Не слушает порт.** Health check в Railway надо отключить, иначе сервис будет считаться упавшим.
- **Не хранит состояние между прогонами.** Память — реестр клиентов в репозитории и сам Битрикс. Контейнер одноразовый.
- **Не коммитит журналы обратно в git.** Журнал пишется внутрь контейнера и исчезает с ним; постоянная копия — отчёт в Телеграме. Если нужна история в репозитории, это отдельная доработка: пуш из контейнера требует токена на запись.
